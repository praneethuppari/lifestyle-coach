# Manual Recipe Import

## What This Feature Does

Allows a user to manually create a custom recipe under their account by submitting recipe metadata in a single API call. No ingredients are attached at this stage — the recipe shell (title, description, macros, instructions, cuisine, timing, tags) is created and persisted.

## Endpoints

### Register a User
```
POST /api/v1/users
```

**Request body:**
```json
{
  "email": "alice@example.com",
  "display_name": "Alice"          // optional
}
```

**Success:** `201 Created` with the created user object.  
**Errors:**
- `409 USER_ALREADY_EXISTS` — email is already registered.
- `422` — email is missing or not a valid email address (Pydantic rejects before the service runs).

---

### Import a Custom Recipe
```
POST /api/v1/users/{user_id}/recipes
```

**Request body:**
```json
{
  "title": "Chicken Tikka Masala",         // required
  "description": "...",                    // optional
  "cuisine": "indian",                     // optional
  "difficulty": "easy",                    // optional: easy | medium | hard
  "prep_time_minutes": 15,                 // optional
  "cook_time_minutes": 30,                 // optional
  "servings": 4,                           // optional
  "instructions": [                        // optional
    { "step": 1, "instruction": "...", "duration_minutes": 5, "tip": null }
  ],
  "calories": 450.0,                       // optional, per serving
  "protein_g": 35.0,
  "carbs_g": 40.0,
  "fat_g": 12.0,
  "fiber_g": 3.0,
  "tags": ["high-protein", "indian"],      // optional, defaults to []
  "image_url": "https://...",              // optional
  "source_url": "https://...",             // optional
  "source_author": "Gordon Ramsay"         // optional
}
```

**Success:** `201 Created` with the full recipe object.  
**Errors:**
- `422` — `title` is missing, or `user_id` in the URL is not a valid UUID.

**System-set fields (not accepted from the caller):**
- `source_type` is always set to `manual`.
- `is_global` is always `false`.
- `is_verified` is always `false`.
- `id`, `created_at`, `updated_at` are generated by the server.

## Architecture

This feature follows the **Repository + Service + Route** pattern (Approach C).

| Layer | File | Responsibility |
|---|---|---|
| Route | `api/routes/users.py`, `api/routes/recipes.py` | Parse HTTP request, call service, return HTTP response |
| Service | `services/users.py`, `services/recipes.py` | Business rules (duplicate email check, setting system fields) |
| Repository | `repositories/users.py`, `repositories/recipes.py` | All SQLAlchemy queries and writes |
| Schema | `schemas/users.py`, `schemas/recipes.py` | Pydantic request/response models |
| Errors | `core/errors.py` | RFC 7807 typed exceptions + handler |

See `docs/learning/error-handling.md` for a detailed explanation of how the error handler works.

## Design Decisions

### Why user_id is in the URL path
The recipe is a resource owned by a user. `/users/{user_id}/recipes` makes the ownership explicit in the URL and is standard REST convention for nested resources. When auth is added, `user_id` will be pulled from the JWT token instead of the URL, and the path will be simplified.

### Ingredients deferred
Including ingredients in the same import request would require resolving ingredient identity (is "chicken breast" in this recipe the same ingredient row as in another?). That normalization problem is a feature of its own. For now, the recipe shell captures everything needed for planning and macro logging at the recipe level.

### Macros on the recipe vs. computed from ingredients
Both will eventually exist. Recipe-level macros are stored here as entered by the user (or parsed from an external source). Once ingredients are linked, computed macros can be derived and compared. Keeping them separate preserves the user's original data.

## Tests

Tests live in `tests/test_users.py` and `tests/test_recipes.py`.

Because the architecture uses a repository layer, tests mock the service via FastAPI's `dependency_overrides` — no database is required to run the test suite. This means tests are fast, isolated, and deterministic.

Coverage includes:
- Happy path (201 with correct body shape)
- Duplicate email conflict (409)
- Missing required fields (422)
- Invalid email format (422)
- Invalid UUID in path (422)
- All optional recipe fields round-trip correctly
- Correct `user_id` is forwarded from the URL to the service

## What Is Not Yet Implemented

- Ingredient lines on a recipe
- Fetching a recipe (`GET /users/{user_id}/recipes/{recipe_id}`)
- Listing a user's recipes (`GET /users/{user_id}/recipes`)
- Updating or deleting a recipe
- Auth — `user_id` is trusted from the URL for now
